# Suggested GitHub Discussion setup for the five TMF pillars

You do not need a separate questionnaire for Giscus to work. Giscus embeds a GitHub Discussion thread. For a more structured expert review, pre-create one Discussion per pillar with the exact title below and ask reviewers to answer the short response template.

## Pillar 1 — Entire Market Architecture
Exact title: `TMF Pillar 1 — Entire Market Architecture`

Suggested prompt:
1. Can this pillar reconstruct your existing market unambiguously?
2. Which field is missing, ambiguous, overlapping, or unnecessary?
3. Would the same fields guide the design of a new DSO-level flexibility market?
4. What should be harmonised across countries, and what should remain local?

## Pillar 2 — Sub-market Coordination
Exact title: `TMF Pillar 2 — Sub-market Coordination`

Suggested prompt:
1. Does the pillar capture how common flexibility resources are allocated among markets/system operators?
2. Are priority/exclusivity, commitment, bid forwarding, and coordination timing sufficiently explicit?
3. What coordination rule is missing for integrating local DSO markets with other markets?
4. Which elements must be harmonised to avoid conflicting activation or double use of flexibility?

## Pillar 3 — Market Optimisation
Exact title: `TMF Pillar 3 — Market Optimisation`

Suggested prompt:
1. Can the current features distinguish how your market is cleared?
2. Are centralised/decentralised/distributed and sequential/simultaneous/independent choices sufficient?
3. Are the optimisation objectives sufficient for DSO-level implementation?
4. What additional optimisation choice should be represented?

## Pillar 4 — Market Operation
Exact title: `TMF Pillar 4 — Market Operation`

Suggested prompt:
1. Are remuneration, remunerated attributes, clearing type, procurement frequency, minimum bid size and bid structure sufficient?
2. Which operational rule is missing for implementation?
3. Which feature is most difficult to harmonise across countries?
4. Which feature should remain adaptable to local market maturity or liquidity?

## Pillar 5 — Network Representation
Exact title: `TMF Pillar 5 — Network Representation`

Suggested prompt:
1. Does the pillar capture enough information about how grid constraints enter the market?
2. Is the timing of network-constraint inclusion sufficiently clear?
3. Can this representation verify physical feasibility while remaining scalable for DSO implementation?
4. What network representation or validation choice is missing?

## Important
The exact titles above match the `data-term` values embedded in the website. Using these exact titles makes the main TMF page and the detailed pillar page resolve to the same Discussion thread.
